# L0 批量速览

目标：让用户在 1 分钟内回答三件事——**老问题是什么、它解决了什么、怎么解决的**，以及**值不值得精读**。
成本约束：只读标题/摘要/引言/相关工作/结论；除勾选后的单篇外，不做全文解析。

**前置动作：先查分区/核心收录。** 写任何摘要块之前，按学科把整批查完：理工医用 2025 中科院分区，中文人文用南核（CSSCI）＋北核，英文人文用 SSCI/A&HCI。字段只写实际结果，不留空、不写"稍后补"，也不写口径解释。

## 每篇的摘要块模板

```
### ① <标题>
- 元信息：<期刊/会议全称> · <年份/日期> · <分区或核心收录> · <IF（有则写）>
  - 科技刊：`2区 Top（计算机科学）· IF 6.2`
  - 中文人文刊：`南核（CSSCI 2025-2026）＋北核（2023）＋AMI 顶级`
  - 计算机会议：`CCF-A（会议）`（第七版，2026）
  - 非计算机会议：`N/A（会议论文）`
- 老问题：<现有工作卡在哪，缺口是什么>（3–5 句）
- 解决了什么：<本文主张>（贡献类型：新问题/新方法/新数据/新评测/理论/系统）（3–5 句）
- 怎么解决的：<输入→核心模块→训练/推理>；最接近工作：<X>，差异：<Y>（3–5 句）
- 结果：<关键数字与对比对象>；摘要与结论一致：是/否/部分
  - 人文社科：写"核心论断 + 证据类型"（文本细读/注疏/史料/概念史），不硬凑数字
- 信息完整度：高（全文）/ 中（摘要+部分）/ 低（仅元数据）
```

**条件字段**：仅当用户已说明目的、并要求从这批里挑选时才追加：

```
- 匹配度：主题 高·中·低 ｜ 方法 高·中·低 ｜ 结论 高·中·低
- 推荐：值得读 / 部分读 / 跳过 —— <一句理由>
```

未说明目的时**不写匹配度、不写推荐、不排序**。

## 一批里有 DOI 解析不到时

1. **先输出能解析的摘要块**，不要等所有 DOI 都成功。
2. 摘要块之后单列“未找到”清单，只写 DOI，不写排查过程和原因。
3. 勾选选项只列能解析的论文；不要为未找到的编号硬编内容。
4. 最后补一句：未找到的可以稍后重试，或用户自行下载 PDF 发来再补。

## 选择选项（放在所有摘要块之后）

**不要输出勾选表。** 优先用交互式提问/多选工具收集（可多选）；工具不可用时才退回编号列表。

先问两件事：**选哪几篇（多选）＋ 范围（全文 / 只方法 / 只实验 / 收藏 / 暂不读）**。

只有选了要读的（全文 / 只方法 / 只实验），下一问才问目的（精读 / 复现 / 找创新点 / 找选题 / 写综述）。全选"收藏"或"暂不读"时，不问目的。

- 找创新点：看这一篇的贡献三要素，回答"它的新意在哪、我能不能用"。
- 找选题：看它没解决什么，回答"我能接着做什么"；重点问空白与失败案例，不问它多好。

退回文本时的格式：

```
要精读哪几篇？（可多选，回复编号即可）
1. ① <标题>
2. ② <标题>
…
另有：全部 / 都不读，换一批
然后告诉我范围：全文 / 只方法 / 只实验
```

用户给出目的并要挑选时：在选项前给 **推荐 + Top 3 排序理由**（只讲为什么先读，不替用户下"哪篇更好"的定论）。
抓取失败的条目单独列在选项之后，标原因，不参与排序。

## 四段抽取要点

**详细度要求**：`老问题` / `解决了什么` / `怎么解决的` 各写 **3–5 句**，必须带具体对象。只写一句视为没写够。老问题要写清现有方法卡在哪、为什么卡；解决了什么要写具体模块和机制；怎么解决要按输入到输出的顺序讲，不要只罗列模块名；结果至少给一个关键数字或对比对象，没有数字就写证据类型。

### 摘要
- 拆成：问题 / 方法 / 主要结果 / 作者结论。
- 标记需验证的说法：`显著提升`、`首次提出`、`SOTA`、`大幅优于`、无基线的百分比。
- 摘要不能替代结论；数字只写摘要里明确写的，不推算。

### 引言
- 动机 → 现有缺口 → 本文切入 → 贡献清单。
- 逐条列作者声称的贡献，并标类型：新问题 / 新方法 / 新数据 / 新评测 / 理论 / 系统。
- 贡献条数异常多或含糊（"提出一个框架"）→ 在推荐理由里点出来。

### 相关工作
- 不逐篇罗列。画：**流派 — 代表工作 — 本文位置 — 与最接近工作的差异**。
- 无独立相关工作章节 → 从引言对比段落抽取，不算缺陷。
- 仍无 → 标"未设独立章节"，从参考文献取最接近的 2–3 篇作替代信号，并降低信息完整度。
- 常见套路要警惕：只对比"弱基线"、只对比"同组旧作"、把综述当对比对象。

### 结论
- 最终结论 / 作者自认局限 / 未来工作 / 结论强度初判。
- **摘要 vs 结论比对**：结论是否收缩了摘要的声称？出现"可能 / 在特定条件下"说明摘要过度声称。

## 推荐档位

推荐 = 建议投入多少阅读成本，不是论文质量评分。

| 档位 | 含义 | 典型特征 |
|---|---|---|
| 值得读 | 建议全文精读（L1 full） | 新问题/新范式；证据链完整；可复用价值高 |
| 部分读 | 只读方法或实验 | 增量集中在某一块；全文读性价比低 |
| 跳过 | 不建议精读 | 组合式增量；结论不量化；与同批已选篇目高度重复 |

判断依据：新颖性、证据充分度、与目的匹配度、同批重复度。
**目的未说明时不输出推荐**；此时只陈述论文事实，让用户自行判断。

## 匹配度与推荐（条件输出）

**只在用户已说明目的、并要求挑选篇目时输出。** 否则整段跳过，不要写"待定"占位。

- 主题匹配：研究对象/任务是否落在用户需求内。
- 方法匹配：方法族是否是用户想要/能用的。
- 结论匹配：结论是否回答了用户的问题（例如用户要工程落地，论文只给理论界 → 低）。
- 三者任一为低，推荐档位最高只能到"部分读"。
- 不要把"论文本身质量"混进匹配度；匹配度只看需求，不看水平。

## 输出纪律

- 一屏内可扫读；不要为每篇写超过 10 行。
- 不编造：分区查不到写"未收录/无法匹配"；计算机会议写 CCF 等级（第七版），查不到写"未收录（CCF 目录无）"；非计算机会议写"N/A（会议论文）"。
- 未能取到正文 → 信息完整度标中/低，并在推荐理由里说明依据仅来自摘要。
