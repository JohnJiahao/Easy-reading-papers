# 分区与数据来源

## 分区口径（按学科分轨，冻结）

**先判学科，再选口径。不要拿中科院分区套中文期刊。**

| 论文类型 | 用什么 | 字段怎么写 | 禁止 |
|---|---|---|---|
| 理工／医（SCI/EI 英文刊） | 中科院 2025 升级版 | `1区 Top（计算机科学）；IF 8.0` | 用 2024/2023 版；用"新锐分区"冒充 |
| 人文社科中文刊 | **南核（CSSCI）＋北核（北大核心）** | `南核（CSSCI 2025-2026）＋北核（2023）＋AMI 顶级` | 编造"1区/2区"；把北核南核换算成分区 |
| 人文社科英文刊 | SSCI／A&HCI 的 JCR 分区 | `SSCI Q1（学科）；IF x.x` | 套中科院分区 |
| 计算机国际会议 | **CCF 第七版（2026）** | `CCF-A（会议）` / `CCF-B` / `CCF-C` | 套中科院分区；把 workshop/short paper 算作主会等级 |
| 非计算机会议 | — | `N/A（会议论文）` | 套任何期刊分区 |

细则：

- **南核＝CSSCI**，分"来源期刊"与"扩展版"，两者要分开写，不能把扩展版写成来源期刊。
- **北核＝《中文核心期刊要目总览》**，用 2023 版；不混用 2020 及更早版本。
- 中文刊没有"几区"这个概念。只查到北核就写"北核"，只查到 CSSCI 扩展就写"CSSCI 扩展"，不要凑成"1区"。
- 补充信号可写 AMI（2022 版）、RCCSE，但**不得替代**南核/北核。
- 中文刊的影响因子是"复合/综合影响因子"，与 JCR IF 不是一回事，写的时候注明来源，查不到就不写。
- 英文人文刊不套中科院分区；科技刊不套 SSCI 分区。
- **CCF 只标会议（及计算机期刊），不标其他学科会议**；只认 full paper / regular paper，workshop、short paper、findings、demo 不按主会等级算。
- CCF 目录官方声明"不作学术评价依据"，标注只作领域信号，卡片里不等同于"分区"。
- 计算机期刊可并列写 CCF 等级（如 `CCF-A 期刊`），但**不替代**中科院分区。

## 查询时机（硬规则）

**收到论文的第一时间就查分区，不拖到写报告或保存。**

1. 拿到 PDF/DOI/标题后，先确认期刊与 ISSN，**先查分区，再写 L0 预览**。
2. 一批多篇时，**先把所有篇的分区查完**，再统一出预览；不要边写边查，避免前几篇有分区、后几篇空着。
3. 查询失败按顺序重试：换关键词 → 换来源 → 隔一会儿再试；三次仍失败才标 `未收录（需手动确认）`。
4. 会话内可复用已查到的结果（同一期刊只查一次），但**不落盘、不建缓存文件**。
5. 禁止因为"先出预览、后补分区"而让 L0 卡片出现空的分区字段。

## 查询流程（实时联网）

**不建本地分区库，不写缓存文件。** 每次用到时实时查：

**科技刊**：

1. 用 ISSN 检索：`<期刊全名> ISSN <issn> 中科院分区 2025`
2. 优先找明确标注"2025 年 3 月升级版"的结果。

**人文社科中文刊**：

1. 检索：`<期刊全名> CSSCI 2025-2026 来源期刊` 与 `<期刊全名> 北大核心 2023`
2. 优先看期刊官网"期刊收录"栏、知网/维普期刊页、国家哲学社会科学文献中心。
3. 区分 CSSCI 来源 / CSSCI 扩展版，分别记录。

**计算机会议**：

1. 检索：`<会议全称/简称> CCF 推荐目录 2026` 或 `CCF-A <简称>`。
2. 以 CCF 官网第七版（2026-03-31 发布）为准，注意会议改名与合并。
3. 先确认论文是 full/regular paper 再套等级；workshop、short paper、findings 另注。

**通用**：

4. 至少两个来源一致才采用；只有一个来源 → 采用但标"单一来源"。
5. 没有联网、查不到、或 ISSN 对不上 → 标 `未收录/无法匹配`。

## 必须避开的坑

| 坑 | 处理 |
|---|---|
| 刊名相似、ISSN 不同 | **必须以 ISSN 为准**，不信刊名 |
| 来源给的是 2024 或 2023 分区 | 弃用，只认 2025 |
| 来源给的是"新锐分区" | 不用，口径不同 |
| 多个来源数值冲突 | 写"存在分歧（A: x / B: y）"，不取平均 |
| 只有 JCR Q1/Q2 | 不转换成分区；人文刊写 SSCI/A&HCI 分区 |
| 中文刊拿北核/南核凑"1区" | 禁止；写"南核＋北核"，中文刊无分区 |
| CSSCI 扩展版写成来源期刊 | 分开写"CSSCI 扩展" |
| 用 2020 版北核冒充 2023 版 | 弃用，只认 2023 版 |
| 计算机会议查不到 | 写 `未收录（CCF 目录无）`，不降级成 N/A 也不猜等级 |
| 用 2022 版 CCF 当最新 | 弃用，用第七版（2026）；旧版只作对照 |
| 把 workshop/short paper 按主会 CCF 等级写 | 单独注明"非 full paper，不计入 CCF 等级" |
| 非计算机会议 | `N/A（会议论文）`，不套期刊分区，也不套 CCF |

## 卡片上的免责声明（必须出现）

> 分区反映发表门槛与社区认可度，最终是否精读仍以需求匹配为准。

分区只作辅助信号，不得单独作为"值得读/跳过"的理由。

## 元数据来源

| 需求 | 来源 |
|---|---|
| DOI 元数据 | Crossref / 出版社页面 |
| arXiv | arXiv abs 页 |
| 摘要 | 出版社页 / arXiv / Crossref abstract（可能缺失） |
| 全文 | PDF；无 PDF 时用出版社 HTML（若有） |

- 元数据缺失字段留空并标"未获取"，不补全。
- 预印本与正式版并存：以正式版为准，标注 arXiv 版本关系。

## DOI 输入的处理顺序

0. **批量先解析**：逐条查，能解析的先汇总；解析失败的单独列"未找到"（只写 DOI），不要因为一条失败阻塞整批。
1. **归一化**：去掉 `https://doi.org/`、`doi:` 前缀和句末标点，只留 `10.xxxx/...`。
2. **L0 题录**：`https://api.crossref.org/works/<doi>`；404 或字段缺失时打开 DOI 落地页核对。摘要优先取 Crossref 的 `abstract`（JATS 需去标签），没有再取出版社页；仍无则记"摘要未获取"。
3. **L0 不下载 PDF**：只用题录 + 摘要，卡片里标信息完整度（高/中/低）。
4. **L1 取全文**，按合法来源顺序尝试：
   - DOI 落地页若标明 Open Access，直接取 PDF；
   - Unpaywall：`https://api.unpaywall.org/v2/<doi>?email=<邮箱>` 看 `best_oa_location`；
   - OpenAlex：`https://api.openalex.org/works/https://doi.org/<doi>` 看 `best_oa_location.pdf_url`；
   - arXiv / PMC（Europe PMC）/ 作者主页 / 机构仓库按标题+作者检索；
   - 都没有 → 请用户上传 PDF，或用户自行通过机构权限下载后发来。
5. **付费墙不绕过**：不使用 Sci-Hub 类来源，不尝试盗用账号/绕过登录；拿不到就停在"仅摘要"。
6. 只拿到摘要时：L0 可做，L1 必须用户补 PDF；报告标"仅摘要，未经正文核验"，禁止写页码、图号、具体实验数字。
7. 下载到的 OA PDF 只放临时目录供解析；**不复制进 `papers/`**（版权与仓库体积），报告里记 DOI 与来源链接即可。
8. **汇报顺序**：先给能解析的预览 → 再列未找到清单 → 再让用户勾选/决定是否精读；对选中但拿不到全文的，建议用户用机构权限自行下载 PDF 后发来。

## 正文获取失败的处理

| 情况 | 标注 |
|---|---|
| 扫描版无文字层 | `未获取正文（扫描版，需 OCR）` |
| 加密 / 权限 | `未获取正文（无权限）` |
| 链接失效 | `未获取正文（链接失效）` |
| 只有摘要 | `仅摘要，未经正文核验` |

上述情况仍可做 L0，但：
- 信息完整度最高记"中"
- 推荐理由必须说明"依据仅来自摘要"
- 禁止引用页码、图表号
- 进入 L1 前需用户补 PDF

## 时效

各轨冻结基准：科技刊 2025 中科院升级版；中文人文刊 CSSCI 2025-2026 版、北核 2023 版、AMI 2022 版；计算机会议 CCF 第七版（2026）。不随年份改写历史记录；报告里注明检索日期与所用户目录版本。
