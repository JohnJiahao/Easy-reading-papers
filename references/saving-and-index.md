# 保存、索引与续写

## 保存前必问

**单篇不询问保存方式**，直接按单篇结构写入主题文件夹。
**≥2 篇时**才问一次：`分开保存 / 合并保存 / 两者都要`；用户不选就不写盘。

## 存什么

保存目录里只留 `report.docx`。生成时先写一个临时 `report.md`（带 frontmatter 和 14 节正文），导出成功后删掉。

### 1. 临时文件里的元数据头（frontmatter）

```yaml
title:
authors:
year:
venue:
doi:
arxiv_id:
zky_partition:      # 科技：中科院2025；中文人文：南核+北核；英文人文：SSCI/A&HCI；计算机会议：CCF；或 未收录 / N/A
purpose:            # 精读/复现/找创新点/找选题/写综述
match:              # 主题·方法·结论 高/中/低
read_scope:         # full / method-only / exp-only
verdict:            # 值得精读/部分精读/收藏
created:
updated:
tags: [领域, 任务, 方法族]
```

### 2. 完整报告（14 节 + 证据附录）
见 `l1-deep-read.md`。不确定项保留"未报告"，不删。

### 3. 导出 Word

```bash
python <skill-dir>/scripts/export_docx.py --latest --remove-source
```

- `--remove-source` 只在导出成功后删除临时 `report.md`；导出失败会保留。
- 公式用 matplotlib 渲染成图片嵌入，Word 里看不到 `$...$` 或 LaTeX 源码。
- 报告里的 `figures/` 图片会一起嵌入。
- 版式：正文仿宋_GB2312 四号，标题二号，英文 Times New Roman，正文首行缩进 2 字符，表格文字居中；一句话结论和关键数字加黄色马克笔底色。
- 依赖：`pip install python-docx matplotlib`；抽图另需 `pymupdf`。

## 目录与命名

默认根目录为**当前工作目录下的 `papers/`**。
保存前问一句："默认放 `papers/`，要换到别的位置吗？"——不回答就用默认；给了路径就用用户的，并记进索引（`base_path`）。

```
papers/
  _index.md                 # 全局索引
  _topics.md                # 主题清单与边界
  _inbox/                   # 暂未归类的论文
  <序号>-<中文主题>/         # 主题文件夹
    _topic.md               # 该主题的定位、收录标准、成员
    <年份>-<一作>-<中文短名>/ # 论文子文件夹
      report.docx           # 正文，公式已转图片
      figures/              # L1 抽图后默认生成
        fig-01.png
        manifest.csv
```

例：
```
papers/02-复合故障/
  _topic.md
  2025-Song-并行胶囊/
papers/01-现代文学/
  2002-凌-沈从文思想价值/
```

- 文件夹用中文，年份和一作保留原样；短名 2–8 个字，用 `-` 连接，不留空格。
- 同名冲突：加 DOI 尾号或 `-2`。
- 索引里仍用英文小写 `paper_id`（如 `2025-song-pcn`）做唯一键，路径按中文文件夹实际写。
- 历史英文文件夹不强制迁移，索引按实际路径记录。

## 分开保存（默认推荐）

每篇一个文件夹，各自一份 `report.docx`。
适合独立检索、独立复读、独立引用。

## 合并保存

```
papers/<YYYY-MM-DD>-合并-<中文主题>/
  report.docx   # 批次概览 + 跨篇对比 + 逐篇（每篇一个二级标题）
  index.md      # 目录、勾选记录、当时的阅读目的
```

合并版必须多一节 **跨篇综述**：共同老问题、方法谱系、结论冲突点、可互相借用的部分。
跨篇综述是合并保存的核心价值，不写就等于只是把文件拼在一起。

## 两者都要

先写单篇文件，再生成合并版（合并版里引用单篇路径或放摘要），避免复制两份正文后不同步。

## 主题归类（读完先归类，再保存）

### 什么时候做
L1 完成后、写盘之前，**问一次**：这篇归到哪个主题？
不确定就放 `_inbox/`，不要硬塞。

### 抽五个归类特征
1. 研究问题（它想解决什么）
2. 方法族（网络结构 / 生成式 / 信号分解 / 对比学习 / 迁移 / 理论）
3. 数据与任务（CWRU、PD、MFPT、自建；诊断 / 预测 / 增强）
4. 结论类型（指标提升 / 新范式 / 机理分析）
5. 与已存论文的重叠点（同问题？同方法？同数据？）

### 归类关键词（判据词表）

主主题由**核心创新点**决定，不是标题里的词频。

**五个维度**
1. 任务：故障诊断 / 剩余寿命预测 / 异常检测 / 数据增强（辅助）
2. 方法族（**主键**）
3. 学习范式：监督 / 无监督 / 半监督 / 自监督 / 零样本 / 小样本
4. 数据与域：CWRU、PD、MFPT、自建、跨域
5. 结论类型：指标提升 / 新范式 / 机理分析

**方法族（领域无关，10 类，主键）**

| 方法族 | 含义 | 线索 | 其他领域的叫法（示意） |
|---|---|---|---|
| 新问题/新范式 | 重新定义任务或评价方式 | 提出新设定、新 benchmark | 医学新诊断范式、社科新测量 |
| 模型结构 | 改主干、模块、连接 | 换 block、加注意力、改 backbone | NLP 新 attention、材料新网络 |
| 表征学习 | 预训练、对比、自监督、embedding | 损失设计与正负样本 | 影像自监督、文本预训练 |
| 生成/增强 | GAN、VAE、diffusion、数据增广 | 造数据、扩样本 | 医学图像合成、表格增广 |
| 输入变换/预处理 | 信号处理、图像变换、分词、特征工程 | 变换域、滤波、patch | 振动包络、遥感波段、文本切分 |
| 训练策略/优化 | 损失、课程学习、元学习、蒸馏 | 训练技巧 | 小样本元学习 |
| 迁移/适配 | 域适应、微调、对齐 | 跨域、跨任务 | 跨医院、跨语言 |
| 低资源/零样本 | few-shot、zero-shot、半监督 | 标签稀缺 | 冷启动推荐、零样本分类 |
| 理论/可解释 | 界、收敛、归因、可解释性 | 证明、分析 | 统计界、可解释模型 |
| 系统/数据/应用 | 数据集、平台、评测、工程落地 | 资源与工程贡献 | 新数据集、开源系统 |

**领域词表（自动生成，不写死）**

技能**不内置任何领域的词**。首次在某库使用时：

1. 扫本批 + 已有论文的标题、摘要、关键词；
2. 抽 10–20 个高频术语（连同同义词），由模型判断归到上面哪一族；
3. 写进 `_topics.md` 的 `## 领域词表`，标注"自动生成，可编辑"；
4. 新论文带来新术语 → 追加，不覆盖；术语变少不删，只标"低频"。

```markdown
## 领域词表（自动生成，可编辑）
| 术语 | 归属族 | 同义词 | 首次出现 |
|---|---|---|---|
| residual shrinkage | 模型结构 | 残差收缩 | 2024-sun-darsn |
```

**判定顺序**
1. 先看**创新点 1** 的主线，选 1 个主族；
2. 再看学习范式：若"零样本/小样本"是立文之本 → 可覆盖主族，归入低资源/零样本；
3. 数据与任务只做子主题或标签，不单独决定主主题；
4. 关键词/词表只作提示。**没有词表时直接按语义判断**，不要求先建词表；
5. 命中多族时，**以主线为准**。

**冲突示例**：⑤ Zero-Sample 同时命中 `contrastive` 与 `zero-sample` → 主主题取 `zero-few-shot`（零样本是立文之本），`contrastive` 只作 tag。

### 判同规则
| 情况 | 处理 |
|---|---|
| 同问题 + 同方法族 | 归入同一主题 |
| 同问题 + 不同方法族 | 同父主题、不同子主题（两级时） |
| 不同问题 | 新主题 |
| 只是"都做轴承" | **不算相关**，不要合并 |

### 归类流程（交互式）

**不能只问"归哪个主题"。必须先把候选摆出来，让用户有依据地选。**

1. 读 `_topics.md` 与 `_index.md`，给出 **2–3 个候选主题**。
2. 按下面格式展示：

| 候选主题 | 一句话范围 | 为什么是它 | 库里最接近的论文 |
|---|---|---|---|
| `01-输入变换` | 改输入表示或编码方式 | 核心创新是频谱→文本 tokenization | 暂无 |
| `04-零样本少样本` | 标签稀缺下的诊断 | 卖点含零样本/少样本迁移 | 暂无 |

- 库为空或没有相近论文 → 写"暂无"，**不要编造**。
- 每个候选的"为什么"要落到这篇论文的**创新点主线**，不能只写关键词命中。
3. 再让用户选：归入某个候选 / 新建主题（给中文文件夹名）/ 放 `_inbox/` / 不保存。
4. 写盘后回写 `_topics.md` 与 `_index.md`。

### `_topics.md` 格式
| 主题文件夹 | 收什么 | 不收什么 | 关键判据 | 成员数 | 更新 |
|---|---|---|---|---|---|---|
| 03-生成式增强 | 用 GAN/VAE 扩增故障样本 | 只做分类网络改进 | 方法族=生成式 | 2 | 2026-11-09 |

### 跨主题论文
一篇同时属于两个主题时：
- 物理文件只放**主主题**文件夹；
- 用 `topics: [a, b]` 在 frontmatter 和索引里记录从属；
- **不要复制两份文件**，否则日后不同步。

### 主题维护（reorganize 模式）
用户说"整理一下 / 重新归类"时：
1. 扫 `_index.md`，输出建议清单：合并、拆子主题、移动、重命名；
2. 每个建议给理由与影响文件列表；
3. 用户确认后执行，并更新所有路径引用。
- 单一主题超过 5 篇 → 检查是否该拆子主题。
- 两个主题高度重叠 → 建议合并，保留一个主题文件夹，另一个记为别名。

## 索引 `papers/_index.md`

| paper_id | 标题 | 主题 | 年份 | tags | 路径 | 范围 | 版本 | 加入 | 更新 |
|---|---|---|---|---|---|---|---|---|---|
| 2024-sun-darsn | … | 01-网络结构 | 2024 | 残差收缩,APReLU | papers/01-网络结构/2024-Sun-DARSN/ | full | v1 | 11-09 | 11-09 |

- 主题列填主题文件夹名；跨主题写 `a; b`。
- 批量保存时另记：`group: 2026-11-09-合并-<中文主题>`。

## 续写模式（过几天又找到几篇）

触发：用户说"存到之前那个文件夹 / 和上次放一起"。

1. **读 `_index.md`**，按 tags / 主题 / 上次目的列出候选文件夹，让用户确认。**不猜路径。**
2. **查重**（DOI → arXiv → 标题+年份+一作）：
   - 已存在 → 更新：重新生成 `report.docx`，`updated` 改日期，索引记修订，旧版可按需留存
   - 不存在 → 新建中文文件夹
3. **防重名**：文件夹冲突加 DOI 尾号 / `-2`。
4. **写入 + 回写**：报告 → 导出 `report.docx` → `_index.md` 追加行。
5. **合并版要重算**：若目标是合并版文件夹，追加新篇并**重新生成跨篇综述**，标 `updated`，旧版不删。
6. **同篇二次精读**（范围不同）：生成 `report-method.docx` / `report-exp.docx`，索引记 `v2 (method-only)`，不覆盖 v1。
7. 找不到匹配文件夹时：宁可问，也不新开一个几乎同名的目录。

若索引不存在：先扫描 `papers/` 反推生成一份，再执行续写。

## 保存后回报模板

```
已保存：
- 文件夹：<绝对路径>
- 文件：report.docx
- 变更：新增 2 篇，更新 1 篇（<标题>）
- 索引：_index.md 已回写
- 精读范围：<full / method-only / exp-only>
```

## 明确不存

- 大段原文（版权 + 体积）
- 中间推理过程、试错记录
- 未验证猜测；必须保留时标 `[推测]`
